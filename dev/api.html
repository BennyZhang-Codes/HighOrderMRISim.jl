HighOrderMRISim.HO_Phantom — Type
obj = HO_Phantom(; x, kwargs...)
obj = HO_Phantom{T}(; x, kwargs...)
obj = HO_Phantom(name, x, y, z, ρ, T1, T2, T2s, Δw, Dλ1, Dλ2, Dθ, ux, uy, uz, csm)

Description

The HO_Phantom struct. Most of its field names are vectors, with each element associated with

a property value representing a spin. This struct serves as an input for the simulation.

Omitting csm creates one ideal receive coil with sensitivity 1 + 0im at every spin: unit amplitude, zero additional phase, and no signal normalization. This is a receive-sensitivity default, not a transmit B1 model. For Float32 or Float64 coordinates, omitted numeric arrays preserve that precision. An explicitly supplied CSM retains the existing constructor behavior; it is not normalized or replaced.

Arguments

  • name: (::String) phantom name
  • x: (::AbstractVector{T<:Real}, [m]) spin x-position vector
  • y: (::AbstractVector{T<:Real}, [m]) spin y-position vector
  • z: (::AbstractVector{T<:Real}, [m]) spin z-position vector
  • ρ: (::AbstractVector{T<:Real}) spin proton density vector
  • T1: (::AbstractVector{T<:Real}, [s]) spin T1 parameter vector
  • T2: (::AbstractVector{T<:Real}, [s]) spin T2 parameter vector
  • T2s: (::AbstractVector{T<:Real}, [s]) spin T2s parameter vector
  • Δw: (::AbstractVector{T<:Real}, [rad/s]) spin off-resonance parameter vector
  • Dλ1: (::AbstractVector{T<:Real}) spin Dλ1 (diffusion) parameter vector
  • Dλ2: (::AbstractVector{T<:Real}) spin Dλ2 (diffusion) parameter vector
  • Dθ: (::AbstractVector{T<:Real}) spin Dθ (diffusion) parameter vector
  • ux: (::Function) displacement field in the x-axis
  • uy: (::Function) displacement field in the y-axis
  • uz: (::Function) displacement field in the z-axis
  • csm: (::AbstractArray{Complex{T}, 2}) receive-sensitivity matrix of shape (length(x), nCoil); the number of coils is size(csm, 2).

Returns

  • obj: (::HO_Phantom) HO_Phantom struct

Examples

Simulation

KomaMRICore.simulate — Method
simulate(obj::HO_Phantom, hoseq::HO_Sequence, sys::Scanner;
         sim_params=Dict(), array_type=nothing, gpus=nothing,
         verbose=true, callbacks=(), w=nothing)

Run the legacy high-order Bloch model with current KomaMRI sequence sampling. The "mat", "state", and "raw" return modes are preserved. Matrix output retains its trailing singleton thread dimension for existing demo scripts.

Both the legacy "Nblocks" setting and the current "max_block_length" and "max_rf_block_length" settings are accepted. Explicit maximum block lengths take precedence. w is retained only for source compatibility; use callbacks instead of the removed Blink progress interface.

High-order fields affect free precession, while RF excitation uses nominal gradients, matching the original package. "implementation" selects "array", "kernel", or "auto" (default). Auto uses the kernel for static CUDA high-order simulations and otherwise preserves the array path. An explicit kernel request errors if unsupported; it never silently discards motion or changes the model. For supported kernels, "coil_combination" selects "gemm" (default, packed cuBLAS), "reduction" (two-stage coil weighting and reduction), or experimental "fused_warp" (precession with subgroup coil reduction; RF retains GEMM). "fused_tiled" additionally reuses small ADC/coil tiles during precession. The fused choices size reusable ADC/packed buffers from the maximum RF ADC count, including zero capacity when RF has no acquisition. Callbacks and raw metadata report "max_adc_per_block", "max_rf_adc_per_block", and "adc_state_buffer_samples"; the caller's parameter dictionary is not changed.

Use array_type=Array for CPU execution or array_type=CUDA.CuArray, gpus=[0, 1] for CUDA execution. GPU IDs are zero-based visible-device IDs, not physical indices when CUDA_VISIBLE_DEVICES remaps devices. These keywords override the legacy "gpu"/"gpu_device" settings; omitting them preserves legacy device selection. Explicit CUDA requests fail rather than fall back to CPU.

Multiple GPUs simulate disjoint contiguous spin ranges through the complete sequence, preserving relaxation and RF history. Signals are summed in device-list order in the requested precision, and final magnetization is joined in original spin order. Only summation order changes. Callbacks receive shard-local arrays; their progress includes shard_index, nshards, gpu_device, and spin_range. Callback invocations are serialized, but blocks from different shards can interleave.

"synchronization" => "auto" (default) relies on CUDA stream ordering between kernel blocks and waits at the end. Callbacks still receive completed block data; array execution retains block fences. Set "synchronization" => "block" to retain the original per-block policy for diagnostics. Neither policy changes sampling, arithmetic precision, RF physics, or coil summation.

For repeated runs, prepare_simulation provides explicit ownership and reuse of device inputs, block views, workers, and buffers. Close the resulting plan when finished; ordinary one-shot calls do not retain a hidden global cache.

Prepared execution

HighOrderMRISim.prepare_simulation — Function
prepare_simulation(obj, hoseq, sys; sim_params=Dict(),
                   array_type=CUDA.CuArray, gpus=nothing)

Prepare an owned, reusable static CUDA high-order simulation. Sampling, device inputs, magnetization, signal/work buffers, block views, and one persistent task per device are reused by simulate(plan; callbacks=(), return_type="mat"). The same precision, Bloch model, coil algorithm, and spin partition are used as in one-shot simulate. CPU/array/moving-coordinate execution retains the one-shot API and is not accepted here.

Inputs are snapshotted. Each run restores model/sequence values and resets magnetization and signal buffers, preserving independent-run semantics even after a callback failure. Callbacks may edit array values but must not rebind arrays or change their shapes. Returned host arrays are independent snapshots. Multiple calls on one plan serialize; recursive use from its callbacks errors.

Call close(plan) in finally to release owned device arrays and join workers. The prepare_simulation(f, obj, hoseq, sys; ...) do-block form closes automatically. Closed plans cannot be run again. No hidden global cache is used.

source

Use simulate(plan; callbacks=(), verbose=true) to run a prepared simulation. Its default return mode comes from the preparation parameters. Override it with return_type="mat", "state", or "raw". Use the do-block form of prepare_simulation or close the plan explicitly with close(plan).

Description

Interpolates trajectory along the 1st dimension using Akima interpolation.

Arguments

  • traj::AbstractArray{<:Real, 2}: trajectory data (2D array, where each row is a point in the trajectory)
  • dt::Float64: time delay between input samples
  • delTime::Float64: time delay to be added or subtracted from time
  • datatime: output sample times in seconds; its precision may differ from traj. Input knots are dt * (0:nSample-1) - delTime; values outside their range are zero.

Keywords

  • intermode::Interpolations.InterpolationType: interpolation mode (default is AkimaMonotonicInterpolation). other Monotonic methods from Interpolations.jl are:
    1. LinearMonotonicInterpolation
    2. FiniteDifferenceMonotonicInterpolation
    3. CardinalMonotonicInterpolation
    4. AkimaMonotonicInterpolation
    5. FritschCarlsonMonotonicInterpolation
    6. FritschButlandMonotonicInterpolation
    7. SteffenMonotonicInterpolation

Returns

  • traj_interp::Matrix{T}: one row per output time, preserving the trajectory's element type.
